PackGuard

An agent that reviews an npm package for security risks before you install it — by reading the code, never running it.

Track: Cybersecurity Opsera · DevSecOps MCP Tigris · storage Daytona · isolation Vercel · serverless

"Inspect without installing." We download the tarball and read it. We never run npm install and never execute fetched code.

The Problem

Installing a package runs its code — before you've read a line

npm install executes lifecycle scripts (preinstall, postinstall) the moment you pull a dependency. Supply-chain attacks live exactly there.

~3M
packages on npm — any can be a typo away from yours
postinstall
runs arbitrary code on your machine, automatically
after install
most scanners check dependencies you've already pulled

Developers vet packages by gut feel — download counts, GitHub stars, a quick glance. There's no fast, safe "look before you leap" check that inspects the actual source without the install step that's already dangerous.

The Solution

Type a name. Get a verdict. Never touch the install button.

PackGuard fetches the package source straight from the registry, unpacks it safely, runs a DevSecOps security scan, and returns a shareable SAFE / RISKY verdict with the exact risky lines.

Core property

Inspect, don't install

Only the .tgz is downloaded and read. No install commands, no lifecycle scripts, no require/eval. Reading code is safe; running it is not.

Real findings

The actual risky lines

Every finding shows category, file, line number and the source snippet — not just a number.

Shared + durable

Public verdict + gallery

Each scan is stored with a public link and joins a growing browsable library of vetted packages.

How It Works · Agents That Act

Automated before, automated after — a deliberate human in the middle

1 · Resolve

npm registry

Validate name, resolve version + tarball URL. Pure serverless.

→
2 · Fetch

Safe-untar

Download .tgz, extract with path-traversal / symlink guards into an isolated dir.

→
3 · Scan

Opsera Agent

Operator runs /security-scan — Semgrep + Gitleaks static analysis.

→
4 · Normalize

Verdict

Map raw output to schema, fail-safe defaults, score → SAFE/RISKY.

→
5 · Store

Tigris + gallery

Upload report + source, mint public URL, persist record.

The scan trigger is a human step (Opsera has no public API) — so we engineered an honest agent that automates everything around it and survives the pause with a durable contract.

Why It's Safe

Hardened extraction, proven by property-based tests

# What PackGuard does ✓ download left-pad-1.3.0.tgz from registry.npmjs.org ✓ untar → ./scan-target/ # treated as read-only data ✓ reject ../escape, absolute paths, symlink escapes, >250MB / >10k entries ✓ read every file · run Semgrep + Gitleaks # What PackGuard NEVER does ✗ npm install / yarn / pnpm ✗ preinstall · postinstall scripts ✗ require() · import() · eval() ✗ execute a single fetched byte

20 correctness properties (fast-check, 100+ runs each) cover containment, rollback, normalization, fail-safe defaults and verdict derivation. Missing data always defaults to RISKY — never silently "safe."

The Output

A verdict you can read, trust, and share

● SAFE

Automated static security review and risk scoring · scan by Opsera (Semgrep + Gitleaks) · static analysis does not detect threats that only appear at run time.

Honest framing is enforced in one shared module: every verdict carries the label, the Opsera attribution and the disclaimer — and forbidden over-claims ("malware detection", "behavioral") are blocked by test.

Architecture

  • web/ — Vite + React + TS, terminal-themed UI, state-machine scan flow
  • api/ — Vercel functions: resolve, scans, scan-records
  • packguard-agent/ — localhost loopback for fetch + safe-untar + upload
  • shared/ — canonical contracts + framing, so UI can't drift from backend

Engineering rigor

  • Spec-driven — 17 requirements in EARS, full design doc
  • 20 properties — property-based tests on all pure logic
  • Fail-safe by default — missing data reads as RISKY
  • Daytona spike — documented YES with reproduction steps
